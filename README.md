# 转接模式（Relay Egress）

**一句话**：本机只负责渲染和解密；浏览器发出的**每一个**请求，都从你自己的 VPS 出去。
目标网站的访问日志里看到的是 VPS 的 IP，不是你家宽的 IP。

它和常见的「代理模式 / 全局模式 / TUN 模式」不是同一类东西：

| | 代理 / 全局 / TUN | 转接模式（本方案） |
|---|---|---|
| 出口在哪，谁说了算 | 代理客户端的规则或系统路由表 | 一段**只有一个上游**的网关代码 |
| 会不会直连 | 规则写错、节点挂掉、DNS 泄漏都可能直连 | 直连**这条代码路径不存在**：上游不是回环地址就拒绝启动 |
| 出口断了怎么办 | 常常"悄悄回落"成直连 | 请求直接失败，宁可不能用 |
| 需要动系统吗 | 系统代理 / 证书库 / TUN 驱动 | 都不动 |

> 这份是**安装办法**。装好后它的样子是：**一个文件夹 + 两个按钮**，没有安装包、没有服务、没有常驻驱动。

---

## 一、它靠什么保证"不会偷偷直连"

**结构**（改不掉，不是"检查"出来的）：

1. `gateway.mjs` 里**只有一条上游** = `127.0.0.1:<隧道端口>`。启动前先验证上游是回环地址，
   不是就直接拒绝启动（退出码 `2`，日志 `UPSTREAM_NOT_LOOPBACK`）。
2. 运行中隧道断了 → 请求**失败**，客户端连接被直接断开。源码里没有"回退直连"这条分支
   （日志表现：`GW_UP_FAIL ... action=client_connection_reset_no_fallback`）。
3. UDP 一律拒绝（SOCKS5 回 `REP=0x07`），不留 QUIC / WebRTC 打洞出去的路。
4. 网关只绑回环 `127.0.0.1` —— 局域网里其它机器也连不上它。

**检查**（运行期发现不对就停）：

5. **出口身份对照**（确定性，每轮真发请求）：分别"经网关"和"经隧道"各取一次出口 IP，两者必须相等，
   且必须不等于本机直连 IP。任何一条不成立 ⇒ 不开浏览器、停链路。
6. **链路上进程出网审计**（抽样补充）：把链路上的进程**及其子进程**的 TCP 连接翻一遍，
   非回环连接数必须是 `0`。

> 为什么两道都要：审计是**抽样**，实测存在"早 5 秒 `AUDIT_OK`、后 5 秒 `AUDIT_LEAK`"的窗口（短命连接）。
> 所以**结构 + 出口身份对照是主，进程审计是辅**。

## 二、需要什么 / 不需要什么

**需要**
- Node 18 或更新（`node -v` 有版本号即可；只装了便携版也行，把全路径写进配置）
- 一台你自己的 VPS（能 SSH 登录、能带私钥免交互登录）
- 本机两个空闲的回环端口（默认 `1080` = 隧道，`8877` = 网关）

**不需要**（这是重点）
- 不要管理员权限 · 不改系统代理 · 不改系统证书库 · 不装防火墙规则 · 不装驱动
- 不依赖任何第三方 npm 包（网关只用 Node 内置模块）
- 不装抓包工具也能用（装了只是多一个"看得见完整 URL"的好处，见第六节）

## 三、安装：Windows（三步）

1. 把 `relay-egress` 这个文件夹放到你自己的目录里（免安装）。
2. 打开 `配置.json`，改两处：
   - `vps`：`你的用户名@你的服务器IP`（例如 `root@203.0.113.10`）
   - `sshKey`：你私钥的路径（例如 `C:\Users\你\.ssh\id_ed25519`，**是私钥，不是 `.pub`**）
3. 双击 `启动.ps1`（或右键"使用 PowerShell 运行"）。它会依次做：

   开 SSH 隧道 → 起网关 → 实测"经网关的出口 IP" 是否 == "经隧道的出口 IP" 且 != "本机直连 IP"
   → 打开一个专用浏览器窗口（该窗口强制走本机网关，从不走系统代理）

   任何一步不过，它会**停下来并告诉你是哪一步**，不会"半开着"让你用家宽上网。

在这个窗口里正常上网即可。`http://ip.3322.net` 显示的是 VPS 的 IP。

- **停**：双击 `停止.ps1`
- **卸载**：删掉整个文件夹（它不往系统里写任何东西）

## 四、安装：macOS / Linux（三行）

```bash
# 1) 隧道：把 你的用户名/你的服务器 换掉
ssh -N -D 127.0.0.1:1080 你的用户名@你的服务器IP &

# 2) 网关（唯一出网口；它只允许拨 127.0.0.1，拨别的会直接拒绝启动）
node gateway.mjs --port 8877 --up 1080 --log ./run/gateway.log --state ./run/state.json

# 3) 一个专用浏览器窗口（网关同时会说 SOCKS5 和 HTTP 代理）
chromium --user-data-dir=./browser-profile --proxy-server="socks5://127.0.0.1:8877" \
         --proxy-bypass-list="<-loopback>" --disable-quic https://example.com/
```

停：关掉浏览器、`Ctrl-C` 掉 node、`kill` 掉那个 `ssh`。
细节见 `Linux或Mac_三行命令.txt`。

## 五、怎么自证"没泄漏"（四条，都能自己复现）

1. **出口对照（最直观）**：在专用窗口里打开 `http://ip.3322.net` → 显示 VPS 的 IP。
   把网关关掉再刷新 → 直接打不开（这正好说明"网关一停就没有网"，而不是"偷偷直连"）。
2. **自证不会直连，不需要服务器**：双击 `自检.ps1`（或 `node gw_selftest.mjs`）。
   它全程只在回环上跑、不碰外网，验 9 条性质：上游非回环→拒绝启动、上游不通→拒绝启动、端口被占→拒绝启动、
   SOCKS5 全程通、HTTP 改写为 origin-form、UDP 一律拒绝、上游断开→请求必失败且无直连兜底、账目不变式。
   期望最后一行：`SELFTEST_OK`（`pass=9 fail=0`）。
3. **链路上进程出网审计（Windows）**：`node _egress_audit.mjs --gw-port 8877 --layer-port 8899`
   期望看到 `AUDIT_NONLOOPBACK=0` 与 `AUDIT_OK`；出现 `AUDIT_LEAK=` 行就是有进程直连了外面。
   它**只读**、不要管理员。`AUDIT_DESC=n` 是靠"子进程"这条规则额外算进来的进程数。
4. **出口身份对照**：启动脚本每次都会做（见第一节第 5 条），这是确定性判据，不看运气。

## 六、可选：想看到"完整网址"（像抓包工具那样）

不加任何东西时，你只能看到"连到了哪个主机"这个级别 —— 因为 HTTPS 是密文，网关只搬不改。
想看到完整 URL + 状态码，就在本机再加一层**解密代理**（whistle / mitmproxy 这类），
并把它的出口指向本网关：

```
浏览器 → 抓包层 127.0.0.1:8899（只解密/只看）→ 网关 127.0.0.1:8877 → 隧道 → VPS → 目标站
```

要点：抓包层**不做出口决策**（它的上游必须是网关），所以"解密"这件事不会带来新的泄漏面。
代价：这个窗口要单独信任抓包层自己那张 CA（**别动系统证书库**）。

## 七、常见故障对照

| 现象 | 多半原因 |
|---|---|
| 提示"找不到私钥" | `配置.json` 里的 `sshKey` 路径不对（要**私钥**，不是 `.pub`） |
| 提示"隧道没通" | 脚本用 `BatchMode`，**不接受交互式密码**；确认地址/端口/私钥，看 `run\tunnel.log` |
| 提示"网关没起来" | 看 `run\gateway.log` 末尾：端口被占（改 `gatewayPort`）／上游连不上（隧道没起）／node 太老 |
| 窗口能开但网页打不开 | 多半是隧道断了 —— 这是**预期行为**（宁可不给你用，也不直连） |
| 想换端口 | 改 `配置.json` 的 `tunnelPort` / `gatewayPort` 后重启 |

## 八、已知边界（诚实说明）

- **VPS 当然看得见你的家宽 IP** —— 它就是你的 SSH 服务端。"没露出来"指的是**目标网站**看不到。
- **这条链路不匿名**：目标站看到的是 VPS 的 IP，仅此而已；不做任何流量混淆。
- **进程审计是抽样，不是保证**：泄漏连接可能很短命，某一次抽样恰好没看到是有可能的。
  真正每次都拦得住的是"结构 + 出口身份对照"。
- **平台差异**：Windows 与 Linux 都真跑过；Windows 有"进程审计"这一层，**Linux/macOS 没有**。
- 本包**不含任何凭据**：`配置.json` 里只有路径和占位符，私钥始终在你自己手里。
- 报告/文档里的端口、进程号、时间戳一定会过期，以你现场为准。
